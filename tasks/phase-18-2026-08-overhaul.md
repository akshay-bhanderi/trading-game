# Phase 18 — 2026-08 UX/Economy Overhaul + Tier 3/4 World Expansion

[← Back to index](../TASK.md)

Status: **Complete.**

> Not part of the original design doc's build order — a large batch of user-directed fixes, redesigns, and a scope expansion, requested in one session after extended real-world play surfaced friction and a few genuine bugs. Ordered smallest/lowest-risk first per the user's own explicit sequencing choice (small fixes → warehouse → bank redesign + CA tab → travel → market/warehouse integration → cargo tier → Tier 3/4 last, since it's the biggest and riskiest).

## Bug fixes

- [x] **Hotel Sell-button mis-tap at max tier** — `RealEstateScreen.tsx`'s Upgrade/Sell button grid used to drop the Upgrade button entirely once a hotel reached its top tier, so Sell slid into Upgrade's old grid slot and got accidentally tapped. Fixed: Sell is now pinned in a stable slot; a disabled "Max tier reached" placeholder takes Upgrade's slot instead of removing it.
- [x] **Newspaper mentioned locked goods/cities** — `newspaper.ts`'s rumor/false-rumor builders picked from the full `GOODS`/`CITIES` pool regardless of what the player had actually unlocked. Added `isEventRelevant()`, applied to both resolution and rumor story candidates; `buildFalseRumorStory` now picks from unlocked-only pools (falling back to the full pool only in the defensive empty-unlocks edge case).
- [x] **Newspaper backlog after multi-day travel** — resolutions used to queue indefinitely until reported; a multi-day trip could dump a large backlog into the next paper opened. Added `CONFIG.events.resolutionStalenessMaxDays` (3) — a resolution older than that is now dropped silently instead of shown.
- [x] **Newspaper frequency** — `CONFIG.events.storiesPerDayMin/Max` reduced from 2-4 to 0-2 (user preference: quieter papers, some days with nothing new).
- [x] **Loan stray-residual default** — interest accruing between typing a repay amount and submitting could leave a tiny residual balance, which would later age past the 15-day grace period and trigger a surprise bank-default prompt even though the player thought they'd repaid in full. Added a "Repay Full" button (`BankScreen.tsx`) that always pays the exact live outstanding balance.
- [x] **Mobile pull-to-refresh / tap-to-select** — added `overscroll-behavior-y: contain` (html/body and `.popup-body`, the actual scroll container behind every popup) and `user-select: none` / `-webkit-touch-callout: none` / `-webkit-tap-highlight-color: transparent` globally (`App.css`), with `input`/`textarea` explicitly opted back into text selection.
- [x] **Leftover placeholder window graphic** — `HubScene.tsx` had a flat, plain-colored 4-pane window `Graphics` block predating the real per-city background art (T070) — visually out of place against it. Removed. Also added a stroke to the canvas-drawn city-name text so it stays legible against any background art.
- [x] **Cargo upgrades had no UI** — `cargo.ts`'s `buyCargoUpgrade` existed since T011 but was never wired to any screen — confirmed via grep, zero UI call sites. Wired into `MarketScreen.tsx` next to the Cargo capacity bar. Likely the real reason "cargo capacity feels permanently stuck" (compounded by `CARGO.startingCapacity` already sitting at 1,499 out of the box, a T029 balance-pass override — see that constant's own comment).

## Redesigns

- [x] **Warehouse Store/Withdraw UI** — replaced the two stacked dropdown+qty rows with a Market-style tabbed panel (Store/Withdraw tabs, -/+ stepper, range slider, Max button — `WarehouseTradePanel`, local to `WarehouseScreen.tsx`). Floor-elevation visual and inline "Build floor N" buttons unchanged, per explicit user request ("I like the design, keep it").
- [x] **Bank — pooled/global deposits** — deposits redesigned from "one `BankAccount.depositBalance` per city, must be physically present to transact" to a single pooled `GameState.deposit` balance reachable from any city, at one flat interest rate (`CONFIG.banking.globalDepositInterestDailyRate`). Loans are explicitly UNCHANGED — still per-city, presence-gated, capped by that city's bank size × rank. Required a save-schema migration (`SCHEMA_VERSION` 1→2, `saveLoad.ts`'s `migrate()` sums any legacy per-city balances into the new pooled field) and touched `types.ts` (`BankAccount` loses `depositBalance`; `GameState` gains `deposit`), `netWorth.ts`, `bank/default.ts` (surrender seizure + zeroing), `tax.ts` (year-end cash→deposit draining collapsed from a per-city loop to single-pool arithmetic across all three sequential bills: tax+plane-maintenance, hotel license fee, warehouse maintenance).
- [x] **Bank UI — stepper/slider parity with Market** — deposit/withdraw and loan take/repay amount entry now use the same `AmountStepper` control (stepper + slider + Max) as `TradePanel.tsx`, instead of a bare number input.
- [x] **CA hiring moved to its own HUD tab** — extracted out of `BankScreen.tsx` into `CAScreen.tsx`, with its own `'ca'` `PopupKind` and HUD button beside Aviation (`Hud.tsx`/`App.tsx`). The bottom bar (now 9 buttons) already had `flex-wrap`, so it wraps to a second row on narrow screens with no CSS changes needed.
- [x] **Travel screen — compact 2-column redesign** — replaced the one-card-per-city + expandable "seen dNN ▾" last-known-price list with a 2-column CSS grid of compact tiles (`.travel-grid`/`.travel-tile`, `TravelScreen.tsx`), each showing fare/days, a one-line "Last visited N days ago" (or "Never visited"), and the Travel button inline in the same tile. Required a new `GameState.lastVisitedDayByCity` field, stamped on arrival (`actions/travel.ts`'s `advanceTravelDay`, using the POST-`advanceDay` day so it reads "0 days ago" immediately) and seeded for the starting city in `newGame.ts`. The remote price-list feature was dropped entirely per the user's explicit choice (not relocated).
- [x] **Market ↔ Warehouse integration** — `MarketScreen.tsx`'s trade panel gained a Cargo/Warehouse destination toggle (shown only when the current city has a built warehouse), letting Buy/Sell act directly on `state.warehouseGoods` instead of always routing through cargo. New engine functions `buyIntoWarehouse`/`sellFromWarehouse` (`warehouse.ts`) mirror `trade.ts`'s `buy`/`sell` shape exactly (same cash/`cumulativeTradeVolume`/`realizedProfitThisFiscalYear` accounting — a warehouse sale still realizes taxable profit per §10), plus a warehouse-capacity check on the buy side.
- [x] **Cargo capacity tiers extended** — two new tiers added above the doc's original 1,500 cap: 3,000 ($1,200,000) and 6,000 ($4,500,000) — continuing the existing cost/capacity curve. Not yet balance-pass-verified (no bot invests in cargo upgrades at all, so the harness can't validate this on its own).

## Tier 3/4 world expansion (biggest scope item, sequenced last per user request)

- [x] **All 15 cities now ship** — added Auren City, Voltspire, Duskfield, Kessler Mines (Tier 3) and Novara Heights, Frosthelm, The Freeport (Tier 4) to `data/cities.ts`, matching §4's table exactly. Tier 4's produces/wants (no such columns in §4's own Tier 4 table) are a documented interpretation call — see that file's header comment.
- [x] **Electronics + Rare Metals now ship** — added to `data/goods.ts`, matching §5's table exactly (Rare Metals' unlock stays tied specifically to Kessler Mines, per its `{kind:'city', cityId:'kessler-mines'}` condition).
- [x] **Verified-generic systems needed NO code changes**: price engine (`deriveCityGoodRole` already derives producer/consumer purely from each city's `produces`/`wants` arrays), unlocks (`checkCityUnlocks`/`checkGoodUnlocks` already generic over any tier present in config), event scheduling (`distinctTiers()`/scope resolution already derived from live `CITIES`/`GOODS` data), the Informant (`isInformantAvailable`/`calcTipAccuracy` already used an ordered bank-size rank + a generic Novara-Heights-id lookup, unreachable-but-ready), hotels/warehouses/aviation (all keyed generically off `City`/`Good` records). This was verified file-by-file BEFORE writing the new data, not assumed.
- [x] **Event table activation** — `mineCollapse` regained Rare Metals in its affected goods (previously dropped, "out of v1 scope"); `techBreakthrough`/`newDepositDiscovered` flipped from `inertNoV1Good` placeholders to real `fixedGoods` entries (Electronics / Rare Metals respectively), with `newDepositDiscovered`'s scope changed from an inert `fixedGlobal` placeholder to `producerCityOfAffectedGoods` (mirrors Mine collapse — now resolves to Kessler Mines, its real source).
- [x] **Travel distance matrix extended** — `travel.ts`'s `tierDistanceDays` generalized from a flat "same-tier=1, else 2" rule to the full §4 rule (`|tierA-tierB|===1` → 2 days, gap of 2+ → 3 days), plus a Frosthelm special case (always 3 days from anywhere except Kessler Mines, 2) that OVERRIDES the tier-based calculation entirely rather than merging into it.
- [x] **The Freeport's flat-tax Special** — `tax.ts`'s `runYearEnd` now checks `state.currentCity === 'the-freeport'` at the moment it runs; if true, taxes at a flat `CONFIG.tax.freeportFlatRate` (12%) instead of the normal CA-tier formula (still subject to the Noob first-year waiver, which has no stated city exception).
- [x] **The Freeport's no-loans Special** — new `City.loansOffered?: boolean` field (`undefined` = true everywhere else); `bank/loans.ts`'s `takeLoan` rejects when the target city's `loansOffered === false`.
- [x] **Design doc updated in the same pass** — §4/§5's scope-fence framing, §9's Deposits section (redesign), §2's cargo tiers, and §13 (the original scope fence, retained for history with a clear "lifted 2026-08" note) all updated to match current behavior, per the doc's own "never let them drift apart" rule.

### Balance status — explicitly NOT fully tuned

A one-off 200-seed/360-day diagnostic run (not a committed test) after wiring in Tier 3/4 showed:
- random bot: flatlines to $0 by day 180/360 (expected — "hover near broke").
- greedy bot: day90 ≈$103k, day180 ≈$241k, day360 ≈$470k — stays under the Tier 3 unlock threshold ($250k) through most of the run, consistent with "ignores news" underperformance; nowhere near the (aspirational, §11) day-180/360 targets, as expected for a weak strategy.
- news bot (the "smart" strategy): day90 ≈$187k (in range), day180 ≈$1.0M (target $1.5-3M — under), day360 ≈$3.7M (target $10-30M — well under). Under target, not exploited over it — no urgent nerf needed, but the day-180/360 targets are not yet actually MET by any strategy.

The pre-existing greedy-bot day-10/day-30 miss (unrelated to this phase — confirmed via `git stash` against the untouched baseline before any of this session's changes) is unaffected either way.

**Follow-up work still open, not done in this phase:** a real iterative balance-tuning pass for Tier 3/4 (adjusting license fees / `cityModifierRanges` / unlock thresholds specifically for the day-180/360 range) — the same kind of effort the original v1 pass took (see `config.ts`'s `CARGO`/`cityModifierRanges`/`EVENTS` comments for how much iteration that required). Until that lands, treat day-180/360 as aspirational, exactly as the original doc already said before this phase, just for a different reason (previously "not reachable at all," now "reachable but under-tuned").

**Operational note:** `npx tsc --noEmit -p .` from the repo root is a silent no-op (root `tsconfig.json` has `"files": []` and relies on project references) — always use `npx tsc -b` or `npx tsc --noEmit -p tsconfig.app.json`. `npx vitest run`/`npm test` with no path filter re-executes `generateBaseline.test.ts`/`generateBaselineV2.test.ts`, which unconditionally overwrite the LOCKED `baseline.v1.json`/`baseline.v2.json` reference files — always exclude them (`--exclude "**/generateBaseline*.test.ts" --exclude "**/generateBaselineV2*.test.ts"`) or path-filter to specific files instead.
